4
The ReAct Pattern — Reason, Act, Observe
~60 seconds
Say
"What you just watched is called the ReAct pattern — Reason, Act, Observe.

The LLM first reasons: 'I need to check stock.' It emits a tool_call. LangGraph intercepts that, runs the check_stock function, appends the result to the message history, and sends everything back to the LLM.

The LLM reads the result — it observes. It reasons again about what to do next. This loop continues until the LLM produces a message with no tool calls. That's the exit. That's the final answer.

The key insight: we didn't program the sequence check → price → delivery into the graph. We wrote tool descriptions and a system prompt. The LLM infers the sequence itself. And when stock is out? The LLM sees in_stock: false and decides on its own to stop."
Point at diagram
Point at each node as you name it. The loop arrow going back is the key visual — it shows this isn't a linear pipeline.
5
Architecture — LangGraph State Machine
~45 seconds
Say
"The implementation is a LangGraph state machine — two nodes connected in a loop.

The agent node is the LLM. It receives the full message history and responds: either with tool_calls, or with plain text if it's done.

The tools node is a ToolNode — it receives the tool_calls, runs each function, and appends the results as ToolMessages.

After every tool execution, we route back to the agent node. After every agent response, a conditional edge checks: any tool_calls? Yes → tools. No → END.

The state is just the conversation history. LangGraph's add_messages reducer handles merging — we never manually manage the list."

8
Three Engineering Decisions That Matter
~75 seconds
Say — one paragraph per decision

1 — LangGraph over plain chains

"A plain LangChain chain is a pipeline — input in, output out, step A feeds step B. Pipelines can't loop. An agent needs to call tools an unknown number of times in an unknown order before it's done. LangGraph gives you a proper state machine with conditional edges. That's what makes autonomous multi-step behaviour possible."

2 — SSE streaming over a JSON endpoint

"I could have made /chat return a plain JSON blob when the agent finishes. But the agent takes up to 90 seconds on NVIDIA's free tier. Without streaming, the UI is frozen for 90 seconds. With streaming, every thought token, every tool call, every result arrives the moment it happens. The user watches the agent reason — that's the difference between 'what is it doing?' and 'I can see exactly what it's doing.'"

3 — Exponential backoff for the NVIDIA API

"NVIDIA's free-tier endpoint is a shared resource. Under concurrent load it returns HTTP 529 — service temporarily overloaded. Without retry logic, that's a raw error message to the user for a condition that usually clears in 10 seconds. The backend now catches that exception, sleeps 5 seconds, tries again. If it fails — 10 seconds. Then 20. Up to 4 attempts. Most overload errors resolve within one or two retries. The user never sees it."
If asked about the async_http_client error you fixed: "When making the agent_node async for the retry sleep, the LLM calls switched to ainvoke(). That needs an async HTTP client for the SSL bypass we need on the corporate proxy. I used the wrong parameter name — the installed version of langchain_openai uses http_async_client, not async_http_client. Wrong name got silently forwarded to the OpenAI API which rejected it. One-line fix once identified."

Quick Reference — If you get questions

Q
Why not just use a plain LLM API call with a loop?
"You can build this with a raw while loop — call the LLM, check if it returned tool_calls, execute them, repeat. LangGraph does exactly that, plus: thread-safe state management, streaming event hooks, checkpointing, observability. You get all of that for free. For a personal project, either works. At production scale, the infrastructure matters."
Q
What if the LLM calls tools in the wrong order?
"The system prompt instructs it to call check_stock first, then price_order, then delivery_eta. The tool descriptions reinforce this — price_order says 'use the SKU returned by check_stock'. In practice, the LLM follows the sequence reliably. If it doesn't, you can add an output parser or a validation step — LangGraph supports adding more nodes. But we haven't needed it."
Q
What does 'state' mean in LangGraph?
"State is just a TypedDict — in our case, a list of messages. Every node reads the full state and returns a partial update. LangGraph merges updates using reducers — the add_messages reducer appends new messages rather than replacing the list. Think of it like Redux for AI agents."
Q
Why NVIDIA NIM instead of OpenAI directly?
"NVIDIA's NIM API is free-tier accessible with my existing API key, and the models — nemotron-3-super-120b — are strong enough for tool-calling tasks. The interface is OpenAI-compatible, so switching to OpenAI or Azure OpenAI is a one-line change to the base_url and model name. The abstraction holds."
